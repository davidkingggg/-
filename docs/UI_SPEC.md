# UI 规范 (UI Spec)

固定页面结构和交互方式，避免开发过程中的风格飘忽不定。

## 2. 核心交互与弹窗规则
- **删除与归档**：所有删除操作优先使用逻辑删除（设为 isArchived=true）。如果必须物理删除，必须弹出明确的二次确认框。
- **表单操作**：简单新增/编辑表单优先使用右侧抽屉 (Drawer) 或居中弹窗 (Modal) 进行展现；复杂表单（如带有多条明细的报价单、采购执行流程等）允许使用独立页面或详情页内编辑区域。
- **操作反馈**：每次保存、更新或归档成功后，必须在页面顶部或右上角显示绿色的成功提示 (Toast/Message)。出错时显示红色提示。
- **页面刷新保留**：表单筛选状态或当前查看的 Tab 页等信息，建议尽量同步至 URL Query 参数中，便于分享与刷新保留状态。

## 3. 主要列表页面（表格）规则
- **顶部区域**：包含搜索框（按名称检索）、关键字段下拉筛选（如品类、阶段、风险标签）、以及新增按钮。
- **表格列**：保持克制，仅展示关键标识信息。例如供应商列表展示：名称、品类、推荐等级、是否有最新报价、阶段、操作栏。
- **操作列**：包含 编辑、详情、归档(删除) 按钮。如果有关联跳转（如查看报价明细），可加对应快捷入口。

## 4. 详情页规则
- 采用页签 (Tabs) 结构。例如供应商详情页包含以下 Tab：
  - 基本信息
  - 联系人
  - 关联报价
  - 评分与考察记录
  - 采购执行记录
  - 风险与备注
