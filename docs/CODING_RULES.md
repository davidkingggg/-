# 编码规范与准则 (Coding Rules)

本文件是后续 Vibe Coding 的最高指导原则，必须严格遵守，以减少生成错误代码的几率。

1. **阅读前置文档**：每次开发新功能或模块前，必须先阅读 `PRODUCT_SPEC.md`、`DATA_MODEL.md` 和 `DEVELOPMENT_PLAN.md`。
2. **数据模型优先**：如果要修改数据库或 Prisma Schema，**必须先更新 `DATA_MODEL.md`**，然后再修改代码和 schema，确保文档与代码永远同步。
3. **变更日志记录**：每完成一个模块或功能，必须更新 `CHANGELOG.md`，写明新增、修改、修复了什么内容，以及已知问题。
4. **编译与检查**：每完成一个模块的开发，必须在本地运行 `npm run build` 和 `npm run lint` 确保没有构建与语法错误。
5. **路径规范**：代码中不允许硬编码绝对路径。用户手动录入或导入的附件路径可以是绝对路径或相对路径，但系统推荐使用相对路径（例如：`files/quotes/xxx.pdf`）。
6. **语言规范**：所有的页面显示文字、表单标签、错误提示、按钮文字等，**必须使用中文**。
7. **纯本地化**：本系统是一个本地优先的个人工作库，**不使用任何云服务**，数据仅保存在本地 SQLite。
8. **安全性与防误操作**：删除操作优先采用“归档”（isArchived 逻辑删除）而非物理删除。
9. **测试强制执行**：新增功能完成时，必须参照 `TEST_PLAN.md` 进行补充或完成对应的手动检查说明。
10. **迁移安全**：重命名列的迁移必须使用 `ALTER TABLE RENAME COLUMN` 或等价的无损迁移步骤，不得用 `DROP` + `ADD` 代替重命名。
